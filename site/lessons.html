Lecciones aprendidas

Qué no volver a descubrir

Resumen operacional de las decisiones que explican la configuración final y de los fallos que no deben reaparecer por regresión.

Workspaces no son artefactos portables

Los symlinks npm creados en Linux no resolvieron como módulos Windows. El staging ahora materializa paquetes internos físicamente.

Verificar la API real de cada versión

La API programática correcta de @electron/packager@20.3.0 es el named export packager.

ASAR sí; pruning genérico no

ASAR fue transparente para el runtime. prune:true borró paquetes internos. El pruning quedó especializado en el staging.

userData compartido es una propiedad del producto

Dos builds vieron la misma SQLite porque representan el mismo producto. Eso permitió validar continuidad entre builds y reinstalaciones.

Squirrel cross-build en WSL es viable

Mono + Wine funcionaron. El soporte i386 fue una necesidad de helpers del toolchain, no del target x64.

Un prefix Wine puede quedar inválido

Tras agregar i386 fue necesario recrear el prefix para resolver kernel32.dll.

El helper 7-Zip debe ser determinista

Las variantes 7z-x64.* existían, pero Squirrel esperaba aliases genéricos. PTL ahora los materializa explícitamente.

Problemas del host no son bugs del producto

Los mirrors Ubuntu por HTTP se degradaron; HTTPS resolvió el bloqueo de APT. El diagnóstico separó routing del build de PTL.

Lifecycle significa más que “abre”

Se probaron uninstall, reinstall, install-over y continuidad de datos, no sólo el primer launch del Setup.exe.

Financial bypass también es arquitectura operativa

Los workflows de Actions fueron retirados porque la cuenta no los puede ejecutar por billing. Los gates se mantienen como comandos deterministas locales y Pages se publica desde rama.

Decisiones protegidas

  • No restaurar roots legacy para Electron.
  • No empaquetar symlinks de workspace.
  • Mantener asar:true.
  • Mantener prune:false mientras el staging materializado siga vigente.
  • No borrar userData durante uninstall.
  • Mantener materialización explícita de 7-Zip mientras la dependencia actual la requiera.
  • No depender del lifecycle script de electron-winstaller.
  • Tratar firma, updates, migraciones de esquema y Linux como slices independientes.
