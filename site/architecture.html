Arquitectura actual

Hexágono local-first con Electron como delivery adapter

La misma composición funcional sirve al runtime local y a desktop. Electron no contiene lógica tributaria: levanta apps/local, abre la UI React y delega casos de uso y persistencia a las capas existentes.

Flujo runtime

flowchart TD E["apps/desktop/main.mjs"] --> L["apps/local/create-local-app"] L --> H["HTTP router"] H --> API["packages/http-api"] API --> A["packages/application"] A --> C["packages/contracts"] A --> Q["packages/sqlite-adapter"] Q --> DB[("node:sqlite")] W["React web/dist"] --> H A --> CORE["packages/core"]

Boundary principal

Regla: apps/desktop puede depender de apps/local; apps/local no puede depender de Electron.

Esto preserva el runtime local, los tests y futuros targets. Windows y el futuro Linux son superficies de entrega sobre el mismo núcleo, no forks funcionales.

Persistencia

La SQLite desktop se resuelve bajo app.getPath('userData')/data/personal-tax-ledger.sqlite. Los binarios instalados y los datos tienen lifecycle separado.
