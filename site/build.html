Construcción y desarrollo

Cómo se construye hoy Personal Tax Ledger

El producto se construye como monorepo Node.js con arquitectura hexagonal, frontend React/Vite, composición local HTTP y un adaptador Electron para desktop. La ruta de build separa desarrollo, runtime staging y artefactos distribuibles.

Quick start de desarrollo

Requisitos actuales: Node.js >=24.15 <25 y npm. No se requiere Docker ni una base externa.

npm ci
npm run dev

La composición local completa también puede ejecutarse con:

npm start

y queda disponible en http://localhost:3001 salvo cambio de PORT.

Build y validación

1. Instalar reproduciblemente

npm ci

El lockfile incluye el tooling desktop. El lifecycle script de electron-winstaller puede quedar bloqueado por npm; PTL no depende de ese side effect.

2. Validar código y arquitectura

npm run lint
npm run typecheck
npm run architecture:check
npm test
npm run test:workspaces

3. Validar consumidores y runtime

npm run build:packages
npm run test:external-consumer
npm run pack:smoke
npm run smoke:local

4. Validar superficie desktop

npm run desktop:check

De código a artefacto Windows

La distribución Windows no empaqueta el workspace directamente. Primero se genera un staging autocontenido para evitar symlinks npm y contenido de desarrollo.

flowchart TD A["npm run build"] --> B["scripts/build-desktop-runtime.mjs"] B --> C[".desktop-runtime"] C --> D["paquetes internos materializados físicamente"] D --> E["@electron/packager"] E --> F["resources/app.asar"] F --> G["portable win32-x64"] G --> H["scripts/create-windows-installer.mjs"] H --> I["electron-winstaller / Squirrel.Windows"] I --> J["PersonalTaxLedger-Setup.exe"]

Comandos directos:

npm run desktop:package:win
npm run desktop:installer:win

Automatización y filosofía del build

Determinista

El repo contiene scripts ejecutables para staging, packaging y creación del instalador; se evita depender de pasos manuales de copiar archivos.

Arquitectura-aware

El pruning lo hace PTL antes de Packager. prune:true de Packager está rechazado porque elimina paquetes internos materializados.

Verificable

Los gates de calidad y packaging están expresados como comandos versionados y reproducibles del repositorio.

Reproducible

El instalador fue regenerado desde npm ci limpio con audit en cero y sin habilitar el install script de electron-winstaller.

Linux: próximo camino

Electron y el staging actual dejan una base técnica favorable para un target Linux, pero Linux todavía no está implementado ni validado. El próximo slice deberá definir formato de distribución, integración de escritorio, ubicación de datos, iconografía, pruebas nativas y lifecycle equivalente al validado en Windows.
