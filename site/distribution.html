Distribución Windows

Configuración final validada

El artefacto final se construye desde un staging autocontenido, se empaqueta con ASAR y se convierte en Setup.exe mediante Squirrel.Windows.

Pipeline

flowchart TD R[Monorepo] --> B[npm run build] B --> T[build-desktop-runtime] T --> D[.desktop-runtime] D --> P[@electron/packager] P --> A[app.asar / win32-x64] A --> Z[materializar 7z.exe + 7z.dll] Z --> S[electron-winstaller] S --> X[PersonalTaxLedger-Setup.exe]

Por qué prune=false

Packager pruning fue probado y eliminó los paquetes internos materializados del staging, provocando ERR_MODULE_NOT_FOUND. PTL usa pruning determinista propio en build-desktop-runtime.mjs, que conoce la arquitectura del monorepo.

Build desde WSL

El build cross-platform quedó validado con Mono + Wine. El soporte i386/WoW64 fue necesario para helpers Windows de Squirrel, aunque el producto final sigue siendo x64.

npm run desktop:check
npm run desktop:package:win
npm run desktop:installer:win

7-Zip determinista

Squirrel esperaba vendor/7z.exe y vendor/7z.dll. El paquete entregaba variantes por arquitectura. El script de PTL detecta os.arch(), valida la variante y materializa explícitamente los aliases antes de invocar Squirrel.

Datos separados de instalación

La SQLite permanece bajo Electron userData. Reinstall, install-over y uninstall/reinstall fueron validados sin pérdida de los datos observados.
